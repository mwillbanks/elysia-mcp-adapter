`getMcpRegistry(app)` resolves route-backed and standalone primitives into the registry used by MCP discovery and invocation. It uses the options applied to that app's `mcp()` plugin, or the adapter defaults when no plugin options are available. Pass a `NormalizedMcpPluginOptions` value as the second argument to resolve the registry with an explicit override.

## `getMcpRegistry`

```ts
function getMcpRegistry(app: Elysia, overrideOptions?: NormalizedMcpPluginOptions): McpRegistry;
```

```ts
import { getMcpRegistry } from "@mwillbanks/elysia-mcp-adapter";

const registry = getMcpRegistry(app);

for (const [name, tool] of registry.tools) {
  console.log(name, tool.description);
}
```

The returned maps are keyed by tool name, resource URI, resource-template URI, and prompt name. Registry entries identify whether they came from a route or an explicit registration.

## Use cases

Use the registry for application diagnostics, tests, or controlled introspection. Normal MCP clients should use `tools/list`, `resources/list`, `resources/templates/list`, and `prompts/list` instead of importing application internals.

```ts
expect(getMcpRegistry(app).tools.has("users.get")).toBe(true);
```

The registry is cached against the route and explicit-registration state. Treat it as a resolved runtime view, not as a mutable configuration API. Programmatic access is trusted introspection; it does not apply wire-request authorization or visibility filters. MCP clients still use the protocol methods, where the adapter enforces the configured access rules.
