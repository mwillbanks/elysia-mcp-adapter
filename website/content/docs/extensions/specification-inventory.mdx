## Eligibility and release policy

A released specification or formally accepted proposal can enter the server implementation queue.
An unapproved contract needs a published draft and evidence linking the specific contract to a
recognized MCP group. A charter for the same topic does not by itself establish ownership.
See the [group charters](https://modelcontextprotocol.io/community/working-interest-groups),
[SEP guidelines](https://modelcontextprotocol.io/community/sep-guidelines), and
[extension lifecycle](https://modelcontextprotocol.io/seps/3392-extension-lifecycle).

- Approved wire revisions retain their documented compatibility. MCP lists Tasks, Skills over MCP,
  and Server Cards as Beta even though each has an approved baseline.
- An unapproved feature exposes one current revision through explicit opt-in. A patch can advance
  the pin and replace its wire contract. Use the documented replacement when an old exact pin is
  rejected. Historical records remain available for provenance.
- A superseded or abandoned feature first receives a deprecation notice with migration guidance.
  A later minor can remove its configuration, capability advertisement, and dispatch.

The [deprecated features register](https://modelcontextprotocol.io/specification/2026-07-28/deprecated)
covers Roots, Sampling, and protocol Logging. Pass file locations as explicit arguments or
resources, call the model provider API from the application, and use OpenTelemetry for observability.
The Sampling include-context values follow Sampling's schedule. OAuth Dynamic Client Registration is
an authorization-server concern. The old HTTP+SSE transport is distinct from Streamable HTTP SSE.

## Toolchain

All ten manifests use reviewed registry latest dependencies. Bun 1.4.4 manages the root and website
lockfiles. Workspace links and public compatibility ranges remain intact. Formatting uses native
`bun fmt`; typechecks use `bun check`. Fallow remains enabled. Standalone Biome, oxlint, and
oxfmt are absent. TypeScript 7.0.2 generates declarations; packed consumers also check TypeScript
5.8.3 compatibility. Fumadocs TypeScript 5.6.0 requires TypeScript 7.1.0-beta. The website's
patch preserves the synchronous compiler API and has a semantic regression test. Nitro's latest
registry tag points to a release candidate. The website uses stable 3.0.0 while the recommended
3.0.1 remains unpublished. CI uses Redis 8.10.3 for real task-provider checks.

## Host responsibilities and boundaries

Hosts approve tools, skills, elicitation, sampling, roots, UI resources, and external calls. Hosts
own user consent, sandboxing, display policy, credential storage, callback policy, and whether
annotations are trusted. Servers must not infer host approval from a capability advertisement.

Servers own authorization, principal isolation, request validation, resource authorization, task
retention, webhook verification, callback address validation, replay limits, and safe error mapping.
Route-backed operations continue through `app.handle(new Request(...))`, preserving Elysia hooks,
guards, parsing, validation, authentication, and response mapping.

The adapter will not automatically execute skills, retrieve evidence references, discover external
interceptor services, or treat action and trust annotations as authorization. Those behaviors need a
normative source and an explicit opt-in contract before implementation.

## Drift and promotion rules

`bun run extensions:check-drift` verifies immutable source hashes and compares active source bytes
at repository default heads. An unrelated repository commit does not imply a contract change.
The check also discovers new public extension repositories and compares the declared GitHub Action
major tags with current upstream releases. It reports missing sources and drift for review.

Before promotion, record the exact proposal's eligibility and add protocol fixtures, affected-path
tests, documentation, and the compatibility decision. Keep superseded pins as audit evidence.
