---
title: Experimental extensions
description: Explore opt-in MCP extensions with evolving wire contracts.
---

Experimental extensions let applications evaluate capabilities whose protocol or implementation can change. Each extension is disabled by default. Review its maturity and protocol requirements, then enable it explicitly.

| Extension                                                            | Protocol surface                                                     | Configuration                                     |
| -------------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------- |
| [Events](/docs/extensions/experimental/events)                       | Modern event discovery, polling, POST streams, and webhooks          | `extensions.events` and `.mcpEvent()`             |
| [Interceptors](/docs/extensions/experimental/interceptors)           | Interceptor discovery, validation, mutation, audit, and local chains | `extensions.interceptors` and `.mcpInterceptor()` |
| [Server Variants](/docs/extensions/experimental/server-variants)     | Legacy initialization, variant sessions, and GET SSE                 | `extensions.variants` with legacy-only transport  |
| [Action Metadata](/docs/extensions/experimental/action-metadata)     | Tool effect and review annotations                                   | Add `io.modelcontextprotocol/action-metadata`     |
| [Trust Annotations](/docs/extensions/experimental/trust-annotations) | Tool result trust and evidence metadata                              | Add `io.modelcontextprotocol/trust-annotations`   |

Each extension has an overview, quick start, configuration reference, and examples. Read its configuration before enabling it. Pin an exported revision constant or use the supported `current` selector.

The [experimental workspace](https://github.com/mwillbanks/elysia-mcp-adapter/tree/main/examples/experimental) exercises interceptors, legacy variants, Action Metadata, and Trust Annotations through adapter requests. The separate [Events workspace](https://github.com/mwillbanks/elysia-mcp-adapter/tree/main/examples/events) covers polling, streams, durable subscriptions, and signed webhook delivery.

The upstream proposal status does not imply client support. Hosts retain user consent, approval, sandboxing, evidence retrieval, and display responsibilities. An annotation never authorizes an operation.
