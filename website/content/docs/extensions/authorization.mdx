---
title: Authorization
description: OAuth protected-resource enforcement and enterprise authorization profiles.
---

The adapter is an OAuth resource server, not an authorization server. Configure its canonical resource URI, trusted authorization-server issuers, required scopes, and an asynchronous access-token verifier.

```ts
app.use(mcp({
  extensions: {
    auth: {
      version: 'current',
      resource: 'https://api.example.com/mcp',
      authorizationServers: ['https://auth.example.com'],
      scopes: ['mcp'],
      verifyAccessToken: async (token) => verifyWithYourAuthorizationServer(token)
    }
  }
}))
```

The verifier returns an immutable normalized principal with `tokenType: "access_token"`, subject and/or client identity, scopes, expiry, verified audience or resource, and optional approved attributes. The adapter independently rejects a non-access-token result, expiry, issuer, and audience/resource mismatch. Raw tokens, assertions, headers, ID tokens, and unverified claims never enter `McpInvocationContext.authorization`.

Protected Resource Metadata is published at the endpoint-specific RFC 9728 path. The root alias is opt-in because multiple MCP endpoints may coexist. The MCP endpoint rejects query-string tokens and malformed Bearer credentials before JSON-RPC parsing. Missing or invalid credentials receive an RFC-compatible `401` challenge; insufficient scopes receive `403` with authoritative scopes and `resource_metadata`.

Use `authorization.requiredScopes` on tools, resources, prompts, or route MCP metadata. Unauthorized primitives are omitted from listing responses and checked again during invocation. The original `Authorization` header is still passed to internal Elysia route invocation so application guards remain authoritative.

The Client Credentials profile advertises `io.modelcontextprotocol/oauth-client-credentials`. The external authorization server must support preregistered clients, `client_credentials`, approved client authentication, the canonical `resource`, audience-bound access tokens, least privilege, and credential rotation.

The Enterprise-Managed Authorization profile advertises `io.modelcontextprotocol/enterprise-managed-authorization`. The external authorization server must advertise ID-JAG support and JWT bearer grants. The MCP endpoint accepts only the resulting access token; it rejects SAML assertions, ID tokens, and ID-JAGs directly.

Out of scope are token endpoints, dynamic client registration hosting, PKCE/browser flows, enterprise SSO, ID-JAG processing, JWKS hosting, token refresh or storage, and IdP provisioning.
